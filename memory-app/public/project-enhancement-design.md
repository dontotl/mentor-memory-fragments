# 기억의 조각 소개 랜딩 개선 설계

작성일: 2026-09-15. 상태: 구현 및 문서 통합 완료, 최종 root audit 대기.

## 1. 목적과 범위

프로젝트 검토자·개발자가 기억의 조각의 사용자 가치, 실제 구성, 기술적 선택의 이유와 한계를 이해하고 같은 페이지에서 로컬 데모를 시작하게 한다.

기존 `memory-app/public/project.html`을 확장한다. 앱 홈(`/`)과 어르신용 인터뷰 화면은 변경하지 않는다. 새 클라우드 인프라, Object Storage, 유료 API 호출, 모델 추가 다운로드는 포함하지 않는다. 과거 테스트 결과와 현재 서버 상태를 구분한다.

디자인: 기존 브랜드 유지형 개선. `DESIGN_VARIANCE=3`, `MOTION_INTENSITY=1`, `VISUAL_DENSITY=4`. 종이색 `#F7F5F0`, 초록 `#1B5E20`, 한국어 시스템 글꼴과 기존 라이트/다크 토큰을 유지한다. 정적 HTML/CSS/JS를 유지하며 새 UI 프레임워크를 도입하지 않는다.

## 2. 현재 페이지 진단

확인한 근거:

- `memory-app/public/project.html`: 사용자 여정, 구성 목록, 아키텍처 별도 열기, MD 전문/다운로드, 상태 조회와 데모 링크가 이미 존재한다.
- `docs/memory-architecture.json`: PWA, Next.js API, SQLite/파일, 음성 서비스, Ollama, 외부 API의 6개 구성 요소와 연결이 정의돼 있다.
- `docs/verification.md`: 2026-09-14 테스트와 CPU 측정, 실패 후 안내 모드 전환, 개인정보·배포 제한을 기록한다.
- `memory-app/src/server/repository.ts`: 설정 스냅샷, 수정 이력, 요청 중복 방지, 암호화, 생성 버전 검증이 구현돼 있다.
- `memory-app/src/server/providers.ts`, `src/hooks/use-audio.ts`, `src/hooks/audio-state.ts`: 로컬/API 경계, 타임아웃, 전사 후 확인, 늦은 응답 무시, 분할 낭독이 구현돼 있다.

유지할 것: 사진 중심 첫 화면, 텍스트 데모 우선, 로컬 저장 원칙, 실제 성능 한계, 기존 URL과 `#journey`, `#architecture`, `#plan`, `#demo` 앵커.

보완할 것:

1. 아키텍처가 별도 링크 뒤에 있어 랜딩만 읽으면 연결 구조가 보이지 않는다.
2. 기술 스택의 이름은 있지만 왜 선택했는지, 어떤 제약을 수용했는지 설명이 부족하다.
3. 녹음 종료·전사·사용자 확인·저장이 구분되지 않아 실시간 음성 모델로 오해할 수 있다.
4. 보안 설명이 요약 수준이라 데이터별 저장/외부 전송 범위가 불분명하다.
5. 긴 계획서 원문과 반복적인 좌우 분할 제목이 읽기 흐름을 끊는다.
6. 원본 MD, 공개 복사본, HTML 전문이 별도여서 수정 시 내용이 어긋날 수 있다.

## 5. Archify 활용 설계

### 전체 구성: 기존 architecture 유지·보강

- 원본: `docs/memory-architecture.json`, 결과: `memory-app/public/architecture.html`.
- 기존 6개 노드의 ID를 유지한다. 구성 요소를 늘리기보다 설명을 보강한다.
- 브라우저/PWA와 로컬 서버를 구분하고, 로컬 서버 안의 API·파일·모델 호출과 선택 외부 API를 분리해 설명한다. “로컬”은 휴대폰 자체 추론이 아니라 연결된 서버 추론이다.
- SQLite는 원문/설정의 지속 저장, 로컬 미디어는 사진 저장이라는 역할을 부연한다.
- 외부 API 점선은 선택 경로이며 장애 시 자동 외부 전환 경로가 아님을 명시한다.
- 공급자 모델 이름과 포트는 실제 코드 기준으로 유지한다. OCI 배포나 클라우드 저장 경로를 추가하지 않는다.

### 처리 과정: sequence 1개 추가

- 새 원본: `docs/memory-interview.sequence.json`, 결과: `memory-app/public/interview-sequence.html`.
- 참가자: 사용자, PWA, Next.js API, 로컬 음성 서비스, 저장소, Ollama.
- 주 흐름: 녹음 시작 → 수동 완료/묵음 → 녹음 구간 전송 → 한국어 전사 반환 → 사용자가 수정·확인 → 턴 저장 → 후속 질문/안내 질문 → 엽서 표시.
- 전사 직후 DB에 턴을 저장하는 것으로 그리지 않는다. 서버는 턴을 먼저 저장한 뒤 질문 생성을 수행한다. 원문 저장과 모델 응답 대기를 하나의 DB 트랜잭션으로 표현하지 않는다.
- 텍스트 모드는 녹음/STT를 생략하고 같은 확인·턴 저장 지점으로 합류함을 캡션으로 표시한다.
- 취소·재시도·실패 분기를 모두 작은 도식에 넣지 않는다. 별도 설명으로 requestId 중복 방지와 늦은 응답 무시를 연결한다.

### 랜딩에 넣는 방법

1. 기본은 Archify 결과에서 검증된 정적 미리보기 이미지와 HTML 텍스트 요약이다. 완성된 viewer HTML을 임의로 수정하거나 일부 DOM을 떼어 복사하지 않는다.
2. 데스크톱에서는 미리보기 아래 `인터랙티브로 보기` 클릭 시 해당 viewer를 지연 로딩한다. iframe에 명확한 title과 예약 높이를 주고, 항상 `전체 화면으로 열기` 링크를 병행한다.
3. 작은 화면에서는 읽을 수 없을 만큼 축소된 iframe을 강제하지 않는다. 요약과 미리보기, 독립 viewer 열기를 기본으로 한다. 키보드·스크린리더 설명은 iframe 밖에도 존재해야 한다.
4. 부모 테마와 iframe을 비공식 postMessage 또는 DOM 조작으로 동기화하지 않는다. viewer 자체의 테마 선택을 유지하고 미리보기 이미지는 부모 테마에 맞게 선택한다.
5. 기본 motion은 none. 시연용 trace는 독립 viewer의 명시적 조작에 한정한다. 설명은 한국어, 도구 고정 메뉴/html lang의 영어 fallback은 기존처럼 고지한다.

생성 시 matching schema/common/example를 읽고 후보를 작성한 뒤 validate → deliver → visual-check 순서를 준수한다. 전달된 HTML을 직접 후편집하지 않는다. 자동 검증과 실제 시각 검토를 구분해 결과를 남긴다.

| 장애 대응 | 시간 제한과 최종 출력 검증, 실패 시 명시적 안내 모드 | 연결됨/모델 ready는 품질·속도·모든 요청의 성공 보증이 아님 |
| 로컬 보호 | 세션 소유권, AES-GCM 설정/본문, 허용 호스트·Origin 검증 | 계정 인증/기기 복구 미구현. 키와 데이터가 같은 서버에 있어 서버 탈취까지 막는 것은 아님 |
| PWA 캐시 | 공개 오프라인 안내만 캐시, 개인 API·사진은 캐시하지 않음 | 인터넷/서버 없이 전체 인터뷰가 되는 오프라인 앱이 아님 |

## 7. 데이터 처리 설명

| 데이터 | 기본 처리·보관 | 외부 전송 조건 |
|---|---|---|
| 업로드 사진 | 로컬 media, 소유권 확인 후 제공 | 현재 원본 사진을 이미지 API에 자동 전송하지 않음 |
| 녹음 음성 | 전사를 위한 임시 처리, 서버 지속 저장 안 함 | STT를 API로 선택한 인터뷰 또는 명시적 연결 테스트 |
| 확인한 글/수정 이력 | SQLite의 암호화된 인터뷰 기록 | TTS를 API로 선택한 인터뷰에서 낭독 요청 시 |
| 삽화 설명 | 사용자가 입력한 설명으로 선택적 이미지 생성 | 명시적 생성 버튼 요청 시 GPT Image API |
| API 키 | 로컬 서버의 암호화 설정, 화면에는 hasKey만 | 지정된 공급자 인증에만 사용 |

사진 파일까지 암호화돼 있다고 표시하지 않는다. “원음 보관 안 함”과 “임시 처리 자체가 없음”을 혼동하지 않는다. 실제 법적 인증이나 완전한 익명성·보안 인증을 주장하지 않는다.

## 8. 실측 및 상태 표시

2026-09-14 검증 기록을 날짜와 조건을 붙여 소개한다. 이번 설계 작업은 성능 재측정이 아니다.

- 장비: M1 Pro 8코어, RAM 16GB. 음성 추론 CPU 4스레드.
- TTS: 길이 8.24초/7.60초의 합성 음성에 서버 41.23초/42.229초.
- STT: 각 2.517초/2.711초. 첫 입력의 `봄에→봄의` 오류도 숨기지 않는다.
- 한 번의 한국어 대본을 두 번 시험한 결과이지 p50/p95나 어르신 발화 평가가 아니다.
- Qwen3 질문은 검증 실행에서 안내 모드로 전환됐고, 회고록 원문 정리는 Ollama 경로가 확인됐다.
- Node 10개/Python 9개 및 Playwright 통과는 당시 코드 기준의 기록이다. 실시간 배지로 표시하지 않는다.
- 현재 상태는 기존 GET `/api/health` 수동 조회로만 표시한다. 조회 시간·미확인·실패 상태를 구분한다. 확인 버튼으로 추론·모델 다운로드를 수행하지 않는다.

미구현/미검증 영역은 별도 작은 영역에 묶는다: 실제 iPhone 마이크, 실제 어르신 발화, 유료 API 실호출, 가족 계정/기기 복구, 운영 배포, 다중 사용자 부하, 실시간 지연 목표.

## 9. 파일과 콘텐츠 관리

변경 범위 제안:

- `memory-app/public/project.html`: 개선된 정적 결과물과 외부 JS 없이 읽을 수 있는 핵심 설명.
- `memory-app/scripts/build-project-guide.mjs`: 로컬 MD를 읽어 공개 복사본과 HTML의 계획서 블록을 동기화하는 빌드 단계. 입력은 지정된 문서만 허용하고 본문을 HTML escape한다.
- `memory-app/guide/project.template.html`: 작성용 템플릿. 재생성으로 수작업 결과가 사라지는 문제를 피하도록 생성본/원본 역할을 분리한다.
- `docs/memory-architecture.json`, `docs/memory-interview.sequence.json`: 도식의 유일한 작성 원본.
- `memory-app/public/architecture.html`, `interview-sequence.html`: 검증 후 생성한 독립 viewer. CSS/JS 수동 수정 금지.
- `memory-app/public/guide-assets/`: 공개 가상 사진·실제 샘플 앱 캡처·검증된 도식 미리보기만 저장.
- `memory-app/tests/e2e_project.py`: 섹션 이동, 문서 동기화 결과, viewer 열기, 상태 실패, 모바일 메뉴를 검증하도록 확장.
- `docs/project-guide-verification.md`: 새 변경분의 검증 범위와 receipt 기록.

기존 `project-plan.md`, `project-verification.md` URL은 유지한다. 문서에 있는 사용자별 절대 경로나 비밀값을 새 공개 자료에 추가하지 않는다. 현재 브라우저의 실제 보관함 기록을 소개용 스크린샷에 사용하지 않는다.

## 10. 승인 후 구현 순서

1. 콘텐츠와 문서 동기화: 추가 섹션 ID·MD 일치·안전한 HTML escaping 실패 테스트부터 작성한다. 원본 템플릿과 문서 빌드를 도입해 기존 페이지와 링크가 유지되는지 확인한다.
2. Archify: 전체 구성 설명을 보강하고 sequence를 작성한다. 각 결과를 showcase validate/deliver한 뒤 미리보기와 전체 보기 경로를 연결한다.
3. 기술 설명·접근성: 위 문구를 주제별로 배치하고 모바일 메뉴·native details·키보드 포커스·양 테마를 구현한다. 추가 JavaScript가 없어도 문서와 데모 링크는 읽고 사용할 수 있게 한다.
4. 연결/예외 상태: 클릭 전 viewer 미로딩, viewer 로드 실패 시 독립 링크, 상태 조회 타임아웃, file://에서 HTTP 데모 링크 이동을 검증한다.
5. 최종 검토: Playwright/Archify 브라우저 검증, 시각 확인, 기존 텍스트 데모 회귀 검증을 수행하고 승인된 작업 파일만 커밋한다.

이 문서는 개선 설계이며 앱 실행·모델 설정·외부 서비스는 변경하지 않는다. 코드 수준의 세부 구현 계획과 실행은 이 설계를 검토한 뒤 진행한다.
